# PR review button -> per-change VS Code environments (EXECUTED, 2026-11-11)

Goal: a button on the Forgejo review surface that spins up a browser VS Code
environment operating against the PR's code. Mechanism: launching the button
creates **two Concourse pipelines** per change — an unpaused **creation**
pipeline and a **paused destruction** pipeline. The creation pipeline has a
step that generates and registers a fresh SSH key scoped to this change; the
destruction pipeline removes the container and revokes every temporary
credential. The git `user.name`/`user.email` inside the box are derived from
the Forgejo account of the user that triggered the launch.

## Architecture (live)

```
repo-review pipeline posts the agent review comment on the PR
  └─ comment ends with a signed "Open in VS Code" badge (the button)
       GET/POST https://ai.<tailnet>:8448/vscode-pr/<owner>/<repo>/<pr>?exp&sig
       (ailab-api; HMAC-SHA256(VSCODE_PR_SIGNING_SECRET,
              "vpr|<verb>|<owner>/<repo>|<pr>|<exp>")[:32])
  click -> ailab-api (containers/ailab-api/vscode_pr_api.py):
  1. validates the named forge user via GET /api/v1/users/<name> and takes
     full_name + email from that profile  (identity requirement)
  2. renders pipelines/vscode-pr-up.yml.tmpl + vscode-pr-down.yml.tmpl
     ({{PLACEHOLDERS}} -> JSON-quoted YAML scalars; leftover-placeholder +
     control-char guards)
  3. fly set-pipeline BOTH:
       vscode-pr-<slug>-up     exposed + UNPAUSED + trigger-job create
       vscode-pr-<slug>-down   exposed + PAUSED (safety by design)
  -up job 'create' (pipeline-lab agents/vscode_pr.py):
     register-ssh-key : ssh-keygen in-task -> Forgejo POST
                        /repos/{owner}/{repo}/keys (read_only, title
                        vscode-pr-<slug>) = the change-scoped temp credential
     start-box        : SSH (dedicated keypair config/concourse/
                        vscode-box_ed25519 -> host sshd as px) runs
                        scripts/vscode-pr-env.sh create: code-server
                        container (digest-pinned codercom/code-server),
                        clone of refs/pull/<n>/head, git identity baked,
                        pool port 3130..3135 -> tailnet doors 8450..8455
     comment          : access link + teardown instructions on the PR; the
                        connection token only via the signed /access page
  -down job 'destroy' (unpause + trigger by hand from the comment link):
     teardown         : vscode-pr-env.sh destroy (container + private key +
                        token + workspace gone) AND forge DELETE /keys/<id>
                        (credential revoked)
     delete-pipelines : removes -up, then its OWN pipeline (build aborts
                        mid-self-delete by design; PR comment already posted)
```

## Button investigation (why this shape)

Forgejo 17.0.1 has **no native review-button / review-prompt feature**: the
real server binary is `/app/gitea/gitea` in the container (the
`/usr/local/bin/{forgejo,gitea}` entries are a 581-byte wrapper script —
grepping those finds nothing; grep the binary), and `grep -a -c -i
'reviewprompt|review-prompt|review_prompt'` returns 0 while no docs page for
it exists on forgejo.org (v17.0 user/admin trees). No custom JS injection
exists either. So the button is markdown in the agent-posted review comment:
a shields.io badge link (renders as a button) carrying an HMAC-signed,
expiring URL into ailab-api; the interstitial page then does the real
pipeline creation. That also solves the identity requirement: the page asks
which forge user triggers the launch, and the value is validated against the
Forgejo user API before anything is created.

## Conventions this feature follows / adds

- Secrets: signing secret generated by `scripts/generate-secrets.sh`
  (`VSCODE_PR_SIGNING_SECRET` in ailab-api/service.env);
  `scripts/pipeline-bootstrap.sh` §6 mirrors wiring values (forge token,
  concourse creds, box SSH key b64, URLs) into ailab-api's env + appends
  `vscode-pr-signing-secret` / `ailab-public-url` to pipeline-vars.yml, and
  installs the box key into `~/.ssh/authorized_keys`. All idempotent.
  `scripts/rotate-secrets.sh` rotates the signing secret and re-mirrors the
  concourse password; re-run pipeline-bootstrap afterwards.
- Ports: box pool **3130–3135** (loopback publishes) with persistent
  tailscale serve doors **https 8450–8455** (`scripts/vscode-pr-doors.sh`,
  LIVE 2026-11-11). services.json untouched: the boxes are transient, not
  registered services; the marker files
  `~/.workspaces/vscode-pr/port-<p>` hold pool allocations.
- Trust: the box SSH keypair grants the Concourse tasks a px shell on the
  host (needed to drive rootless podman; the worker is already privileged —
  deliberate, same posture as the vscode box's host-socket mount). The
  change-scoped deploy key is READ-ONLY and short-lived.

## E2E test record (live, PR pipeline/pilot-cli#1, 2026-11-11)

1. POST signed launch (user `pipeline`) -> `fly pipelines`:
   `vscode-pr-pipeline-pilot-cli-1-up` (unpaused) +
   `vscode-pr-pipeline-pilot-cli-1-down` (PAUSED) — both created + the -up
   `create` job triggered.
2. create job #7 (after fixing the failures below): **succeeded 28s** —
   `registered deploy key title=vscode-pr-pipeline-pilot-cli-1 read_only=True`,
   box `Up`, loopback + tailnet door 200, PR #1 comment posted with the
   editor link + access-page link + destroy-job link.
3. Box contract: `refs/pull/1/head -> pr-1` cloned over SSH with the fresh
   deploy key (log: `Switched to branch 'pr-1'`); git identity inside the
   box = forge profile: `pipeline` / `pipeline@noreply.forge.<tailnet>.ts.net`;
   key 0600 owned by the box user; code-server login: correct password ->
   302 /(session), wrong -> 200 rejected.
4. Destroy cycle: unpause -down + trigger -> container GONE, forge keys
   list `[]`, state dir empty (port marker released), `fly pipelines`
   grep vscode-pr -> 0 (both pipelines self-deleted; the final build aborts
   as it deletes its own pipeline - documented behavior).
5. ailab-access lists the live box with reviewer identity + door URL.

Live fixes the e2e forced (each one caught by the real run, not theory):
- ssh-keygen needs the artifact parent dir created (build #1 failure).
- pipeline tasks need the write:issue review token, not the plain forge
  token (comment 403 -> token re-mirrored + re-launched to re-bake).
- code-server 4.145.2 auth: no --password-file; --password rejected on
  argv; $PASSWORD dropped across the launcher re-exec (child-environ
  probe); config.yaml heredoc is the working shape (printf's single
  quotes broke the enclosing bash -c string).
